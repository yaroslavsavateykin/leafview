# LeafView terminal/renderer audit — 2026-10-19

## Status: partial improvement, NOT acceptance-ready

Working tree was clean at b514450. Fetched origin and fast-forwarded main to
14483bb (latest terminal/scroll safety fixes); changes isolated on
`audit/graphics-lifecycle`. No user changes overwritten, no push.

Actual environment: Ubuntu, Ghostty 1.3.0-dev+0000000 (GTK/OpenGL), tmux 3.6.
Existing tmux has allow-passthrough=on and focus-events=on. Experimental native
runs used separate Ghostty processes (`--gtk-single-instance=false`) and separate
tmux sockets, never the working session. No global tmux/Ghostty config changes.

## Findings and changes

1. **Native transport traffic amplification (confirmed).** ratatui-image 11.0.8
   encodes raw RGBA into 4096-character base64 packets and puts the whole transfer
   into a Ratatui cell. Each scroll creates another transfer. Multi-megabyte
   frames generate thousands of passthrough commands and temporary copies.
   New local Kitty widget uses PNG (`f=100`), unchanged raster pixels, bounded
   3072-byte chunks and the same Unicode placement technique. Transmission occurs
   only once per encoded image. Process-owned image ID and targeted cleanup remain.
   Unit tests decode transmitted PNG back to identical RGBA, verify chunk
   reconstruction, tmux framing and no retransmission on unchanged redraw.
   PNG does not guarantee smaller transfers for all imagery (see raster test).

2. **Scroll starvation on an uncached raster (code-level finding, regression
   tested).** Every crop request previously cancelled Poppler even if document,
   page and raster width were identical. A long raster could repeatedly restart
   under scroll autorepeat. Raster cancellation now uses those three keys;
   generation still rejects obsolete crops/results. A 2 ms repeated-scroll test
   verifies raster work reaches cache without stopping input. Zoom/page/revision
   changes still cancel stale work. Scroll cache hits do not invoke Poppler.

3. **Hover speculation violated cache policy (code-level finding).** Hover jobs
   called `cached`, allowing eviction of visible rasters, and only cancelled on
   shutdown. Now they use non-evicting admission and cancel on generation changes.

4. **Offsets committed before display (code-level finding).** Completed raster
   coordinates were applied before encoding finished. Coordinates are now
   committed with accepted encoded geometry, avoiding stale completion overwrites
   of input received during encoding.

5. **Signal termination skipped RAII cleanup (confirmed by original code).** Added
   signal-hook flags for TERM/HUP/INT; the UI exits through its normal cleanup
   path. PTY tests verify exact termios restoration during navigation. This does
   not protect against SIGKILL, OOM or terminal emulator crashes. Signal handlers
   are installed in viewer_loop, not during pre-terminal document opening.

6. **External graphics corruption remains (confirmed).** Existing user journal
   contains raw-RGBA `unexpected length image` / Kitty `EINVAL` errors. In a new
   isolated PNG test with raster.pdf, tmux pane splits/resizing/focus switching,
   Ghostty logged `wuffs_png: decode err=zlib: bad checksum` then Kitty `EINVAL`.
   LeafView exited 0 and restored TTY; Ghostty/tmux were not observed crashing.
   Root cause of stream corruption is NOT isolated: tmux passthrough scheduling,
   detach/visibility transitions, truncation and concurrent pane streams need
   further minimization. This evidence does not prove a Ghostty implementation
   bug or prove the cause of the historical session loss.

## Architecture review

- `main.rs`: synchronous terminal draw/write remains on UI thread (can block on
  terminal backpressure); 75 ms request throttle, bounded completion channel,
  one pending encoding job plus latest replacement. No unbounded event draining.
  OS watcher is bounded and watches parent for atomic saves. Focus gained still
  reschedules rendering; identical clamped edge scrolls may re-encode redundantly.
- `render.rs`: one-slot latest-wins mailbox; generation checking; 96 MiB/8-entry
  byte-accounted LRU; crops share cached page raster before copying viewport.
  Two Rayon workers prefetch neighbors; visible work cancels outdated prefetch.
  Hover worker is bounded to one but may duplicate a concurrent visible raster.
  Shutdown sets cancellation, wakes mailbox, joins worker and pool.
- `workers.rs`: bounded input/output channels; cancellable output retry (upstream
  fix), owned joins. Worker panic/disconnection is not fully surfaced on every
  path; encoder itself is finite but cannot be interrupted mid-PNG.
- `process.rs`: prlimit constrains child address space/output/CPU, tempfiles avoid
  stdout/stderr pipe deadlock, 10 ms cancellation polling, kill/wait guard.
  Limits are per subprocess, NOT aggregate RAM. Multiple prefetched pages and
  encoded/cropped buffers can exceed the cache budget. Large PDFs can fail limits
  gracefully rather than render; cache limit is not total process memory limit.
- `document.rs`: immutable <=512 MiB snapshots; metadata detects in-place writes;
  failed reload preserves old document. Copy and extraction run off UI on reload;
  initial open occurs before terminal initialization. Links are parsed in a
  resource-limited helper process rather than an uninterruptible UI parser.
- `links.rs`/`view.rs`: bounded annotation extraction, supported destination types,
  rotated crop geometry, sanitization, only HTTP(S), argv-based browser launch,
  bounded history and process cleanup. Existing Poppler pixel and coordinate
  tests remain passing. Real native visual/link alignment not visually verified.
- Crossterm capability query precedes mouse reporting; Ratatui init panic hook
  plus normal restoration guard; targeted Kitty delete avoids neighboring panes.
  Same-ID replacement bounds terminal resources but interrupted transfers require
  further investigation. No blanket all-images deletion added.

## Actual experiments

Python `scripts/terminal-stress.py` proxies a PTY through a real Ghostty, including
real terminal capability responses. It records output bytes, transfer count,
LeafView peak RSS, thread/child counts, CPU samples, exact termios and quit time.
It is intentionally separate from the headless `pty-smoke.py`.
Raw per-run JSON/logs: `/tmp/leafview-*.json`, `/tmp/leafview-ghostty-*.log`.

| run | duration | output bytes | peak LeafView KiB | transfers | quit s |
|---|---:|---:|---:|---:|---:|
| baseline raw RGBA, math, direct | 35 s | 150331516 | 138344 | 13 | .060 |
| final PNG, math, direct | 35 s | 1653642 | 93268 | 11 | .025 |
| PNG, vector, tmux (earlier iteration) | 35 s | 916523 | 133752 | 11 | .017 |
| PNG, long, tmux + resize + SIGTERM | 65 s | 2605305 | 128456 | 21 | .051 |
| PNG, real 14.6 MB quantum chemistry PDF, tmux + resize | 65 s | 2227851 | 99624 | 3 | .026 |
| final PNG, raster, tmux + split/focus/resize | 65 s | 106183696 | 108188 | 17 | .023 |
| Halfblocks, math, direct | 35 s | 118442 | 36008 | 0 | .013 |

All listed runs exited 0, exact child TTY restored, max 8 threads and max 1 direct
child observed (sampling misses Rayon thread children). Final raster run had the
checksum error described above. Different numbers of accepted transfers mean
these are workload measurements, NOT exact equal-frame benchmarks. Math total
traffic decreased ~91x; peak LeafView RSS ~33%. Sampled main-process CPU:
baseline 1.29 s vs final 1.30 s (does not include child CPU). No rigorous render,
encode, cache-hit, cancellation or input-to-display latency telemetry yet.

Headless smoke tests: navigation storm >1000 events, atomic replacement, failed
reload, tiny viewport/resize, Typst link hover/click/back/browser failure, quit,
plus newly added TERM/HUP/INT cleanup. Unit/integration tests cover Poppler pixel
geometry, links, bounded output, cancellation, cache, workers and latest-wins.

## Diagnostics and limitations

Kernel journal shows an earlier OOM killed **tinymist** (~19 GB anonymous RSS),
not proof LeafView or Ghostty was OOM-killed. `coredumpctl` unavailable. Existing
Ghostty still running after tests; pre-existing LeafView processes were not
terminated. No crashes of the disposable Ghostty/tmux observed. Other protocols
(Sixel/iTerm2) were not validated as supported alternatives on this Ghostty.
GNOME screenshot D-Bus denied access; therefore no screenshot/visual inspection
of fonts, formulas, scaling or artifacts was performed. Lossless pixel tests are
not a replacement for that. Real Ghostty window resizing and tmux detach/attach,
repeated reopen/close soak and real continuous Typst compilation are outstanding;
PTY resize and atomic fixture saves are not their equivalents.

## Delivery decision

All required build/test commands pass (see final response); synthetic profiling
benchmark remains ignored by normal test suite. Native Kitty improvements are
available with `LEAFVIEW_GRAPHICS=native`, but automatic Ghostty+tmux protection
is deliberately unchanged because native corruption reproduced. Do NOT describe
Halfblocks as the satisfactory final solution. Do NOT install this experimental
branch over the user's working binary until native protocol errors and visual
checks are resolved. No installation or push was performed. This audit does not
meet the user's full acceptance criterion yet.
